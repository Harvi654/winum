## Problem as the user saw it

Inventor 2026.4 update: PatchFiles failed with 1603 on .NET assemblies and on old files larger than 8 MB.

## Cause and fix

Wine MR 3870 (Aidan Khoury, 2023, never merged) ported to 11.19: 32-bit PE patching; plus old files larger than the LZXD window. Not original code of this project.

## Wine test

None in the production patch. The separate
[v2 signature candidate](../../patches/candidates/mspatcha-signature-v2/README.md)
adds an original Wine test for the Windows-measured signature/normalization
API subset. Its exact-body standalone test passed 50 checks on Windows 10
x86_64/i686. It does not apply or decode PA19 data, so this is not full-patch
L1 and does not close the missing producer/decoder fixture gate.

## Draft for maintainer decision (2026-11-10): subset L1 and decoder exception

**Proposal only; the active marker stays missing.** Do not promote this
whole patch as l1 on the strength of the signature unit.

Covered by the exact Windows L1: GetFilePatchSignatureByBuffer's generated
1 KiB raw CRC32/MD5 cases, a raw 9 MiB+17-byte signature, and a minimal
original PE32 image with default/disabled normalization flags, plus
NormalizeFileForPatchSignature on fresh copies. The 50 checks on each
architecture cover signatures, output termination, changed-byte counts
(including six PE32 bytes for the signature fixups), successful results
and the preserved error sentinel. They do not call ApplyPatchToFile*.
Running an i686 signature EXE is not a test of PA19 PE32 reconstruction;
signing a large raw buffer is not a test of LZXD's old-file window.

Not covered: PA19 application to PE32/.NET images, its relocation/import/
resource processing, and the old-file-larger-than-window path that needs
reference-prefix selection (the reported 8 MiB case). Windows has the
corresponding APIs. Our allowed original-fixture toolchain currently has
no reproducible PA19 producer for those branches. It therefore cannot yet
supply native old/patch/new triples and assert reconstructed bytes for
these cases. This is a fixture/tooling gap, not a claim that native Windows
lacks the feature or that an open producer is impossible.

Proposed exact exception reason, **only if accepted by the maintainer**:

> l3-only: targeted PA19 PE32 and old-file-larger-than-LZXD-window inputs cannot currently be generated by our original open-tool fixture chain; keep signature-only native L1 separate, the existing apply_patch smoke and recorded Inventor updater L4, with original decoder-fixture validation open.

Available reproducers/evidence, with their actual limits:

- [Our original generated-data program and native harness](../wine-repro/mspatcha-pa19/README.md),
  sources measure.c/test-body.h/l1.c and builder
  scripts/build-l1-mspatcha-signature.sh. It explicitly reports
  pa19_decode_covered=0; it must not be renamed a decoder L3.
- Wine 11.20's existing mspatcha_test.exe apply_patch unit exercises its
  supplied small upstream fixtures and complete output-byte comparisons.
  The cross review records a local x86_64 patched run (2145 checks,
  zero failures); all-1 reports no changed apply_patch failure. This is
  an existing upstream decoder smoke, not an original generated PE32 or
  >8 MiB reference regression reproducer, and not a new native L1 here.
- The maintainer's Inventor 2026.4 update L4 is the real reported case:
  former PatchFiles 1603 on 32-bit assemblies/large old files, update
  succeeds with the workaround. Vendor payloads stay local; no archive,
  DLL, extracted patch bytes or inspected vendor internals are requested.

A proper original synthetic decoder L3 is still missing. The draft
exception explicitly retains that weakness; a signature pass alone does
not satisfy AGENTS.md's reproducer requirement. The maintainer must decide
whether the existing limited decoder smoke plus updater L4 justify a
release exception, or defer promotion until a targeted original producer
exists. Do not silently treat this draft as an already approved exception.

Follow-up replacing the exception: generate documented PA19/LZXD framing
from original old/new bytes, test PE32 normalization on/off and old lengths
below/equal/above the reference window, require actual old-prefix references,
compare the entire result, and include corrupt/truncated/wrong-old controls.
Then measure native ApplyPatchToFile* and run the same fixtures on Wine.
No such new decoder test or native pass is claimed in this proposal.
