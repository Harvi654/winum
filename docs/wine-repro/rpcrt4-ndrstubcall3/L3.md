# NdrStubCall3: L3 reproducer (Wine only)

Decision of the maintainer, 2026-11-09: `rpcrt4-ndrstubcall3.patch` gets an
L3-only exception. Windows has the function (x86_64 only), but a valid
call needs NDR64 format tables, which only Microsoft's MIDL generates
(`/protocol all`); widl and every other open tool produce NDR tables only,
and the Windows measurement above (`README.md`) could therefore not reach
the server through NdrStubCall3. Wine's COM sends NDR on both sides
(`ndr64_client_call`), so the NDR64 path is never taken in Wine; the patch
uses the NDR entry of the interface. Inventor's Stress Analysis Mesh View
works with it (L4).

The reproducer is the COM program of this directory (`com-measure.c`, a
real cross-apartment call through a widl proxy) with the server metadata
changed per scenario. Expected results are those of Wine with the patch:

| Program | Server metadata | Expected (patched Wine, x86_64) | Unpatched Wine |
| --- | --- | --- | --- |
| `ndrstub-l3-both` | NDR64 entry first (no tables), then the NDR entry: the `/protocol all` layout | `CALL hr=00000000 value=42`, `server_calls=1`, `functional=1` | `EXPORT ... available=0` |
| `ndrstub-l3-ndr64-only` | only an NDR64 entry, no NDR tables | `CALL hr=80070725` (RPC_X_WRONG_STUB_VERSION, raised by the patch), `server_calls=0`; Wine log has `NDR64 syntax is not supported` | `available=0` |
| `ndrstub-l3-fallback` | no entries, NDR tables in the server info | `CALL hr=00000000 value=42`, `functional=1` | `available=0` |

i686: the patch exports NdrStubCall3 on win64 only, as Windows does; the
i686 programs report `available=0` everywhere.

## Run (maintainer, Linux)

The programs are in the main MEASURE bundle (`docs/wine-repro/measure-bundle.list`,
names above). Download the bundle of the latest "Build MEASURE bundle" run,
then, with a patched winum build and the distribution's Wine:

```bash
export BUNDLE=~/measure-l3
export WINEPREFIX=~/.wine-l3-ndrstubcall3
export WINEDEBUG=fixme+rpc
cd "$BUNDLE"
for n in both ndr64-only fallback; do echo "== $n"; wine ndrstub-l3-$n-x86_64.exe 2>&1 | grep -E 'L3 |EXPORT|CALL |SUMMARY|NDR64'; done
```

Run the loop once with `wine` from winum (`export PATH=<winum>/bin:$PATH`)
and once with the distribution's Wine; send only the filtered lines. The
prefix is a throwaway one, not an Inventor or SOLIDWORKS prefix.

## Shared CI runner (2026-11-11)

The [shared L3 workflow/runner](../l3-ci.md) builds these unchanged programs
with the existing MEASURE builder and `l3.list`. It runs x86_64 and i686
probes using the full CI runtime and the distribution Wine, each in its
own throwaway prefix. No separate bundle download or prefix setup is needed.
The table above remains the interpretation; collection does not assert a pass.

## Result 2026-11-11

Run 42999903587 ([record](../l3-ci-2026-11-11/README.md)): all three x86_64
scenarios as in the table, i686 `available=0`, system Wine `available=0`.
The ndr64-only row first said RPC_E_SERVERFAULT (0x80010105); the run
returned 0x80070725, the HRESULT of the RPC_X_WRONG_STUB_VERSION the patch
raises. The row was a wrong prediction and is corrected above.
