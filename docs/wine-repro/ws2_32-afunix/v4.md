# AF_UNIX v4 review measurements

The v3 review found a reparse tag being overwritten in the handle
information path, an ambiguous Winsock address conversion failure
and a fallback that opens any unhandled reparse point for security.
The original tests cover FindFirstFile, an unbound ConnectEx rejection
and security on the AF_UNIX socket itself. This follow-up measures the
adjacent behavior before changing the candidate.

## Offline Windows 10

Extract the afunix-v4-measure artifact and verify SHA256SUMS on Linux.
Copy the two afunix-v4 EXEs and run-measure.bat into a new folder in the
offline Windows 10 snapshot. Double-click run-measure.bat. It creates
fresh sample directories, runs both architectures and refuses to
overwrite existing output files.

The program reports handle attribute/tag and stat queries on a socket,
bind/connect with short declared lengths on a valid backing buffer,
names on both ends of a connection from an explicitly bound client
and the result of bound ConnectEx. It also creates a disposable file
with a private synthetic reparse tag and reports named DACL query and
setting the same DACL. A setup failure is reported as such. A failure
to set the synthetic tag leaves that measurement inconclusive.

Return only exitcodes.txt, result-x86_64.txt and result-i686.txt.
No private filenames, paths or security descriptors are printed.

## Native Linux host peer

On Linux, from the unpacked bundle directory:

```bash
export WINUM_ROOT="$HOME/.local/share/winum/winum-11.22-1-afunix-x86_64"
python3 run-host-peer.py "$WINUM_ROOT/bin/wine" "$PWD"
```

Use the AF_UNIX candidate runtime. The script makes a fresh temporary
prefix, removes its Z: mapping and starts a native Linux socket
listener in a private directory outside the prefix. Each PE client
uses Wine's explicit Unix path syntax to exchange PING/PONG directly
with the listener. It reports both results. Return the two client
lines and the host_peer_both_architectures line. This is a Linux
interoperability check. Windows expectations come from the separate
offline measurement.

Use `--connectex` to check the overlapped path as well. The Linux peer
sends PONG immediately and closes. The client checks pending completion,
reads the payload, and queries the peer name after closure. This covers
the host-close case reported by independent review. Poll timing can vary.

Use `--measure` to also print the two MEASURE runs under the
candidate in that same temporary prefix. The workflow runs this
comparison on the pinned v3 artifact from run 44080539901.

This probe does not change an installed Inventor prefix, contact
spacenavd or require a SpaceMouse. The real device test still needs
the SpaceMouse integration to select the direct transport.

## Results

### Wine 11.22 with AF_UNIX v3

Both architectures produced the same observations in
[run 44395176853](https://github.com/Harvi654/winum/actions/runs/44395176853),
using the compiled v3 candidate `c11a4f8`.

| Probe | Wine v3 |
| --- | --- |
| FileAttributeTagInfo and FileStatInformation | Success, attributes `0x420`, tag `0` |
| Address lengths 0 and 1 | bind returns 10014; connect returns 10022 |
| Explicitly bound client | Connect succeeds; client getsockname and server getpeername both report an unnamed address of length 110 |
| Bound ConnectEx | Success; updating the context succeeds; same address observations |
| Private synthetic tag | Normal open fails with 1920, named DACL query and setting the same DACL succeed |
| Linux host peer with Z: removed | Both PE clients complete PING/PONG |

The host test confirms the transport used by a future direct SpaceMouse
client. The hardware and the actual spacenavd endpoint were outside
this test.

### Offline Windows 10 22H2 (2026-11-18)

Windows build 19045.6466. The x86_64 and i686 programs both exited 0
and reported the same values.

| Probe | Windows |
| --- | --- |
| FileAttributeTagInfo and FileStatInformation | Success, attributes `0x420` and tag `0x80000023` on both calls |
| Declared lengths 0 and 1 over a valid address buffer | Both bind and connect fail with `WSAEFAULT` (10014) |
| Synchronous connect from an explicitly bound client | Client getsockname returns `bound-client` (15 bytes), client getpeername returns `listener` (11 bytes) |
| Bound ConnectEx | Returns FALSE with `WSA_IO_PENDING` (997), completes with 0 bytes, and `SO_UPDATE_CONNECT_CONTEXT` succeeds. Client getsockname returns `bound-client` (15 bytes), getpeername returns `listener` (110 bytes) |
| Listener side for both connect calls | accept and getpeername return `bound-client` (110 bytes), getsockname returns `listener` (11 bytes) |
| Private synthetic tag | Ordinary open fails with 1920. GetSecurityInfo, GetNamedSecurityInfo and SetNamedSecurityInfo with the same DACL all return 0 |

Wine's security fallback matched the synthetic tag as well as the socket
case in this probe. Restricting it to AF_UNIX would regress the measured
case. The v3 ACL representation limitation for AF_UNIX still applies.

The regression assertions are shared by the native L1 harness and the
candidate's Wine test. The L1 harness can be built with
`scripts/build-l1-ws2_32-afunix.sh`. In the offline VM, run the
bundled `run-tests.bat` from a fresh folder and return the two result
files and `exitcodes.txt`.

### Wine 11.22 with revised AF_UNIX v4 (2026-11-19)

[Run 44406951061](https://github.com/Harvi654/winum/actions/runs/44406951061)
tested `36b088f` on x86_64 and i386. The candidate artifact is
[14478932428](https://github.com/Harvi654/winum/actions/runs/44406951061/artifacts/14478932428).
The measured behavior was the same on both architectures.

| Probe | Revised Wine v4 |
| --- | --- |
| Handle metadata and short connect | Both file queries return attributes `0x420` and tag `0x80000023`. Declared lengths 0 and 1 return `WSAEFAULT`. |
| Bound client names | Client getsockname gives `bound-client` (15 bytes). Client getpeername gives `listener` (11 bytes for connect, 110 for ConnectEx). |
| Bound ConnectEx | Reports pending (997), completes with zero bytes and accepts the context update. |
| Listener side | accept and server getpeername return an unnamed peer (110 bytes). Windows returns the bound client name here. |
| Linux peer with Z: removed | Both PE builds pass PING/PONG and the ConnectEx immediate-close probe. |

L2 found zero new hard failures in 12 suite/architecture pairs compared
with v3 and zero in 12 pairs compared with the test-only baseline.
The sock unit on v4 had eight fewer todos on each architecture than
v3 (393 vs. 401), four skips in each run and the same five hard
failure locations. The assertion totals differed by 172 (x86_64)
and 398 (i386). The two TCP select assertions flagged in the first
v4 run also failed on the revised run's test-only baseline.
