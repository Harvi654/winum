## Status bar investigation (2026-11-07) - read in full

`docs/wine-repro/comctl32-statusbar-erase/README.md`. Summary:

1. Windows 10 (your MEASURE): unthemed status bars paint their background
   in `WM_PAINT` always; a themed v6 status bar paints none there and keeps
   what `WM_ERASEBKGND` left; `SB_SETTEXT` erases in v6 only.
2. Under Wine: for themed v6 the current
   `patches/comctl32-statusbar-erase-background.patch` (v1) matches
   Windows in every measured operation; vanilla does not. For v5 it is the
   other way round (v1 is wrong there).
3. Inventor's overlapping status text is **not** caused by that patch.
   Traces (`trace-summary.py`, `+statusbar,+win,+message`, limited
   `+relay`): every invalidation asks for an erase, Inventor fills the
   erase DC with `ExtTextOutW(ETO_OPAQUE)` and returns 1, Wine's paint
   boxes stay the same - before and after GPU ray tracing alike.
4. The overlap appears only once GPU ray tracing has started (a Vulkan
   swapchain through vkd3d-proton in a child window of Inventor's main
   window) **and** the main window is maximised. Restored (not
   maximised): correct. Maximised again: overlap, the old and new texts a
   few pixels apart vertically, other UI shifted too. The same inside a
   Wine virtual desktop, so not the window manager.
   Not reproduced: 11.20-6 with EGL, colour bits build with EGL or GLX,
   all on the RX 580 without ray tracing.
