# HTTP same-position seek v2: Windows-derived body-continuity test

Original, AI-assisted (Codex), LGPL-2.1-or-later. Candidate only; the
production patch, test marker and patches/series are unchanged.

## Native basis and scope

Our own [loopback MEASURE](../../../docs/wine-repro/wininet-http-same-position-seek/README.md)
completed all 12 cases on offline Windows 10 x86_64/i686 on 2026-11-09,
with matching observations. After a 17-byte prefix, cached Content-Length
FILE_CURRENT+0 and FILE_BEGIN=17 return 17/error 0. Chunked/close-delimited
cached seeks and all measured NO_CACHE_WRITE current-position seeks return
INVALID_SET_FILE_POINTER/error 12016. Every body retains all 16384 generated
bytes, reaches EOF and uses exactly one server-observed request. No-seek
controls also preserve all data and use one request.

The one-line implementation change is identical to production: retain the
read buffer when the requested position already equals content_pos. No
framing, caching, error or other seek behavior is changed by this candidate.
The new test block is added to dlls/wininet/tests/http.c and runs at its
entry before the existing callback/event setup. It uses the original
MEASURE's generated bytes, exact response headers, API arguments and flags.
An added PID/tick URL suffix isolates this run's own cache entries; neither
the route prefix nor the response framing/content changes. Only those own
URLs receive best-effort cache deletion after their handles close.

The loopback actor has its own ephemeral listener, stop event and counters.
It shares no listener, callback, event or response fixture with the existing
HTTP tests. Their server/integration paths were read; this block is original
code from our measurement, not a copy of existing response arrays. WSAStartup
and cleanup are balanced for this own listener, so the subsequent suite can
initialize its usual server independently. There is no DNS, proxy, external
network, credential, application or UI dependency for this new block/native
bundle. The rest of Wine's existing http test retains its usual behavior.

TLS, Range requests, gzip, async WinINet, persistent connections, redirects,
different-position seeks and large downloads are outside this regression.
NO_CACHE_WRITE FILE_BEGIN was not measured and is not asserted.

## Assertions and known independent Wine gap

The target cached-length seek result/error, all prefix/body/EOF comparisons,
case counts and per-case/total request counts use ordinary ok(). No todo
hides buffer corruption or an extra request. Vanilla's buffer reset is
predicted to fail body continuity; runtime pairing must still observe that.

Wine's current HTTPREQ_SetFilePointer does not reject cached chunked/close-
delimited same-position calls as Windows did. Only those result/error checks
have todo_wine_if; their body comparisons stay ordinary. NO_CACHE_WRITE
rejection is ordinary too. The source predicts eight expected todo failures
in Wine, but this is not yet a runtime result. The candidate deliberately
does not expand the implementation fix to that separate framing-support gap.
On native Windows every assertion, including those Wine-only todos, is
ordinary. The standalone wrapper does the same explicitly.

## Native L1 bundle

```sh
bash scripts/build-l1-http-same-seek.sh /path/to/NEW-output
```

Before compiling, the builder checks the entire helper/test block extracted
from the candidate against test-body.h. The same body compiles unchanged
for x86_64/i686 with -Wall -Wextra -Werror, using the common original
asInvoker/Windows-10 manifest. No BEGIN/END markers are added to Wine.
The entry is also in the main measure list; use this builder for parity.

The actor owns its accepted sockets, and the main thread keeps its state
alive until join. Stop/join failure terminates only this test process before
state/listener release. Header/prefix/body loops and case entry share a
45-second cooperative budget; socket timeouts are two seconds and WinINet
timeouts four seconds. A single in-flight call may overrun the cooperative
deadline. The native wrapper additionally has an independent 60-second
watchdog. A timeout exits 2, never a pass. Worker setup/send/close faults are
counted and asserted on the main thread after join, avoiding concurrent
assertion-counter writes. Normal handles, sockets and Winsock resources
are released; cache cleanup is only best effort for the own URLs.

Copy the complete output into a fresh offline Windows 10 directory and run
run-measure.bat. Return result-http-same-seek-l1-x86_64.txt,
result-http-same-seek-l1-i686.txt and exitcodes.txt, including failed or
partial results. Successful execution should report 200 checks, zero
failures, completed_cases=12 and requests=12, exit 0 on each architecture.
No dialogs or application setup are needed. This assertion run is pending;
the previous MEASURE alone is not native L1.

existing series position, keeping every other production entry. Do not
apply both versions or edit patches/series. All 62 entries apply with
--fuzz=0 using this candidate on upstream Wine 11.20 commit
7298a818b79446bae153b8d5aa27235ab3703bf9, source archive SHA-256

pass. Complete wininet.dll and wininet_test.exe PE targets link for x86_64
and i386, with the new block integrated in the existing HTTP test unit.
